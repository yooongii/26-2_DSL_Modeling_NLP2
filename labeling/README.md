# 리뷰 마이닝 — 숙소가 안 알려주는 비용 찾기

숙박 예약 사이트의 리뷰에서 **공식 표기에 없는 추가비용**을 찾아낸다.
주차비·리조트피·보증금·도시세처럼, 예약할 땐 안 보이다가 현장에서 청구되는 것들이다.

**[▶ 데모 — 직접 눌러보기](https://claude.ai/code/artifact/adba41a1-c942-4cc7-badd-31bd63a9aa24)**
검사 패널이 실제로 작동하고, 분석 리포트도 들어 있다.

> 현재 단계는 **규칙 기반 베이스라인**이다. 학습 모델은 아직 없다.
> 규칙이 못 가르는 문장이 얼마나 되는지를 수치로 재는 것이 목적이다.

**처음이라면 → [라벨링-가이드.md](라벨링-가이드.md)**
수집부터 라벨링·채점까지 클릭 단위로 적어둔 문서다. 이 README는 그 다음에 볼 참고 문서다.

## 구성

| 파일 | 역할 | 어디서 도나 |
|---|---|---|
| `collect-reviews.js` | 리뷰·정책 수집 | 브라우저 콘솔 |
| `inspect.js` | 수집이 실패할 때 원인을 보는 패널 | 브라우저 콘솔 |
| `md2json.py` | 팀원이 정리한 `md/*.md` → `data/*.json` | 터미널 |
| `analyze.py` | 비용 언급 분류·집계, HTML 리포트 생성 | 터미널 |
| `label.py` | 라벨링 CSV 생성·병합, 규칙 베이스라인 채점 | 터미널 |
| `export.py` | 텍스트 원고로 변환 | 터미널 |
| `test-*.mjs` | 회귀 테스트 3종 | 터미널 |

## 사용법

데이터가 들어오는 길이 두 갈래다. **A-1**(팀원 md)이든 **A-2**(직접 수집)든
`data/`에 모이고, 그 뒤 B·C는 같다.

### A-1. 팀원이 정리한 md 받기 (터미널)

받은 `.md`를 `md/` 폴더에 넣고:

```bash
python md2json.py        # md/*.md → data/*.json
```

숙소 이름으로 묶고, 약관은 이름이 접두사로 일치하는 숙소에 `roomPolicies`로 붙인다.
`## 약관 파트` / `## [약관 파트]`, `전문(자세히 보기):` / `원문:` 같은 담당자별 표기 차이를 흡수한다.

> md에는 **작성일·평점·공식 표기가 없다.** 최근 리뷰 가중과 표기 충돌 탐지는
> md 입력에서 동작하지 않는다. 비용 언급 집계·라벨링에는 지장이 없다.

### A-2. 직접 수집 (브라우저)

1. 숙소 **상세 페이지**를 연다
2. 후기 영역이 화면에 보일 때까지 스크롤한다
   → 리뷰는 lazy load라, 한 번도 화면에 안 나온 섹션은 DOM에 없다
3. 후기 위의 **"작성 언어"를 한국어**로 맞춘다 (분석기 키워드가 한국어)
4. **F12 → Console** → `collect-reviews.js` 전체를 붙여넣는다
   → `✅ collect-reviews 준비됨 [버전 ...]`
5. 저장 폴더를 한 번 지정한다 (Chrome·Edge)
   ```js
   await pickSaveFolder()   // data/ 폴더 선택 → 이후 자동 저장
   ```
6. 수집한다
   ```js
   await collectReviews({ maxPages: 40 })   // 약 200건
   ```

**`maxPages`를 꼭 지정한다.** 호텔에 따라 페이지가 수천 개다. 끝나면 종료 사유가 찍힌다 —
`마지막 페이지` / `maxPages 도달` / `내용이 안 바뀜`.

#### 자동 페이지 넘김이 멈출 때

사람이 직접 넘기는 모드가 있다. 깨질 구석이 없다.

```js
watchReviews()        // 켜고 → 직접 1, 2, 3… 페이지를 클릭
await saveWatched()   // 다 모았으면 저장
```

#### 그 밖에 막힐 때

| 상황 | 해결 |
|---|---|
| 리뷰 목록을 못 찾거나 엉뚱한 걸 잡음 | `inspect.js`를 이어 붙여넣고 [탐색] 탭에서 직접 선택 |
| 콘솔만으로 지정 | Elements 탭에서 목록 클릭(`$0`) → `await collectReviews({ container: $0 })` |
| 모달을 이미 열어둠 | `await collectReviews({ skipModal: true })` |

### B. 분석 (터미널)

```bash
cd review-mining
python analyze.py
```

`data/*.json`을 읽어 `out/` 아래에 만든다. 표준 라이브러리만 쓴다.

| 파일 | 용도 |
|---|---|
| **`리포트.html`** | 브라우저로 열면 판정 근거가 문장에 하이라이트된다 |
| `집계.md` | 핵심 지표 표 |
| `애매한-문장.md` | 규칙이 못 가른 문장 — 모델이 필요한 구간 |
| `비용언급-문장.md` · `무료라는-문장.md` | 판정별 문장 |
| `후보.jsonl` | 라벨링용 입력 — `label.py`가 읽는다 |

> `analyze.py`는 실행할 때마다 `out/`을 통째로 다시 쓴다.
> **`후보.jsonl` 안에서 라벨을 채우면 다음 실행에 날아간다.** 라벨은 `label.py`로 `labels/`에 뺀다.

### C. 라벨링과 채점 (터미널)

```bash
python label.py init     # out/후보.jsonl → labels/라벨링.csv (기존 라벨은 유지)
#                        # 엑셀로 열어 gold 칸에 1 / 0 / ? 를 채운다
python label.py score    # 규칙 베이스라인 P·R·F1 + ambiguous 회복 가능량
```

`labels/`는 `analyze.py`가 건드리지 않는다. 리뷰를 더 모아 `init`을 다시 돌려도
이미 채운 라벨은 `cand_id`로 매칭해 그대로 옮기고 새 후보만 덧붙인다.

자세한 절차는 [라벨링-가이드.md](라벨링-가이드.md).

### D. 원고 변환

```bash
python export.py --checkin 2026-11-13 --category 리조트 --no-policy
```

`제출-원고.txt`가 나온다. `--no-policy`는 리뷰만, `--all-reviews`는 필터 없이 전부.

## 판정 방식

**키워드만 세면 "주차는 무료라서 편했어요"까지 전부 걸린다.** 그래서 세 단계로 거른다.

### 1. 문장 분리
리뷰를 마침표·물음표·줄바꿈으로 자른다.

### 2. 키워드 + 편의시설 게이트

```
주차비 · 리조트피 · 보증금 · 도시세 · 청소비 · 조식 · 인원추가 · 세금/수수료 · 현장결제
```

이 중 **`조식`·`주차`·`세금`은 그 자체로 비용이 아니라 편의시설 이름**이다.
호텔 리뷰에 지천으로 깔려 있어서, 문장에 비용 맥락(`요금·가격·추가·별도·유료·불포함`)이
같이 있을 때만 후보로 친다.

> 실측(리조트 2곳 383건): 이 게이트가 후보 102건 중 **90건(88%)을 소음으로 걷어냈다.**

### 3. 주변 25자의 단서로 3분류

| 판정 | 조건 | 예 |
|---|---|---|
| `mention` | 비용 단서만 | "주차비를 현장에서 **따로 받더라**고요" |
| `negated` | 부정 단서만 | "주차는 **무료**라서 편했습니다" |
| `ambiguous` | 둘 다 있거나 둘 다 없음 | "청소비가 좀 비싼 편이지만" |

문장 전체가 아니라 **키워드 주변만** 보는 이유: "주차는 무료인데 조식은 따로 받아요"에서
전체를 보면 두 단서가 다 잡혀 판정이 뒤집힌다.

### 규칙의 한계 — 이게 측정 대상이다

`ambiguous` 건수가 곧 **"규칙으로는 여기까지"**라는 증거다. 원리적으로 못 푸는 예:

> "인원 추가 요금이 있다는 안내가 **명확해서 좋았어요**"
> → 규칙은 '추가 요금'만 보고 비용 발생으로 판정. 실제로는 **칭찬**

> "조식 **포함**으로 예약했는데 마지막 날 **추가 요금**을 받고"
> → 부정 단서와 비용 단서가 충돌 → 판정 불가. 실제로는 **명백한 표기 위반**

문장의 뜻을 봐야 풀린다. 다음 단계(분류기)가 넘어야 할 선이 지금 이 규칙이다.

## 리뷰 목록을 찾는 방법

선택자를 하드코딩하지 않는다. 사이트마다 클래스명이 다르고 수시로 바뀐다.

**① 후보 자격** — "날짜가 있고 본문이 15자 이상"인 자식이 3개 이상이고 전체의 절반을 넘을 것

**② 순위** — 개수가 아니라 **리뷰다움**으로 정한다

| 신호 | 방향 |
|---|---|
| 카드마다 평점이 있다 | ➕ |
| 본문이 문장이다 (라벨 나열이 아니라) | ➕ |
| 카드에 가격이 있다 | ➖ 객실 목록의 특징 |
| 카드에 예약 버튼이 있다 | ➖ |

개수로 고르면 **항목이 많은 객실 목록이 리뷰 목록을 이긴다.**
객실 카드에도 날짜(무료취소 기한)와 긴 설명이 있어 '리뷰 모양'으로 채점되기 때문이다.

**③ 카드 판정** — 본문 15~4000자 + 날짜 표기 존재.
날짜 조건이 편의시설 목록·푸터를 거르고, 길이 조건이 달력 그리드(`2026. 9. 3.`)를 거른다.

## 사이트별로 확인된 것

| 발견 | 대응 |
|---|---|
| 리뷰가 **페이지당 5개**로 끊긴다 | 다음 버튼·숫자 버튼을 눌러가며 수집 |
| 페이지를 넘기면 목록 `<ol>`이 **통째로 교체**된다 | 매번 살아있는지 확인하고 모달 안에서 다시 찾는다 |
| 리뷰 목록에 **호텔 답글이 섞인다** (한 사이트 실측 27%) | 구조 신호(`답변일`, `Dear ○○,`, 서명)로 판별해 제외 |
| 평점 척도가 다르다 (5점 / 10점) | 척도를 추정해 `ratingScale`과 함께 저장 |
| URL에 숫자 ID가 없는 사이트 | 경로 슬러그를 ID로 사용 |
| 답글이 리뷰 카드 **안에** 있다 | 본문 추출에서 답글 블록을 제외 |

## 수집되는 데이터

```json
{
  "site": "agoda",
  "listingId": "hilton-okinawa-chatan-resort",
  "listingName": "힐튼 오키나와 자탄 리조트",
  "collectorVersion": "2026-08-29-e",
  "official": ["무료 Wi-Fi", "조식 포함", "무료 취소"],
  "policy": { "cancellation": ["체크인 당일 취소 시 34% 부과…"] },
  "reviewCount": 192,
  "guestReviewCount": 192,
  "reviews": [
    { "text": "조식 포함으로 예약했는데 마지막 날 추가 요금을 받고…",
      "date": "2026년 8월", "rating": 6.4, "ratingScale": 10 }
  ]
}
```

| 필드 | 쓰임 |
|---|---|
| `official` | 숙소가 공식적으로 약속한 것 — 리뷰와 대조할 기준 |
| `reviews[].date` | 신선도 (오래된 리뷰의 정책은 지금과 다를 수 있다) |
| `isHotelReply` | 사업자 답글 표시 — 분석에서 제외된다 |

`data/`와 `out/`은 커밋하지 않는다. 리뷰 원문은 로컬 분석 전용이다.

## 테스트

```bash
node test-heuristic.mjs                  # 수집기 휴리스틱 (78개)
node test-inspect.mjs                    # 검사 패널 (16개)
node test-report.mjs out/리포트.html      # 리포트 렌더링
```

가짜 DOM에 함정을 심어두고 검사한다 — 편의시설 목록, 날짜만 있는 달력 그리드,
사진 갤러리의 "모두 보기"(리뷰 버튼과 문구가 동일), 객실 목록(항목이 리뷰보다 많음),
카드 안에 든 호텔 답글, 페이지 이동 시 목록 교체.

브라우저 없이 돌리려고 `linkedom`을 쓴다. 없으면 테스트를 건너뛴다.

## 알려진 한계

- **수집기는 수동 실행 도구다.** 스크롤·클릭이 필요해 자동화 파이프라인에 넣을 수 없다
- **비용 언급은 드물다.** 리조트 2곳 383건에서 5건(1.3%). 숙소를 늘리거나
  평점 낮은 순으로 정렬해 불만 리뷰를 모으는 편이 효율적이다
- **한국어 전용.** 키워드가 한국어라 다른 언어 리뷰는 버려진다
