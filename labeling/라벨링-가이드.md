# 처음부터 끝까지 — 리뷰 수집 → 분석 → 라벨링

리뷰를 모아서, 그 안에 **"숙소가 안 알려준 추가비용"** 얘기가 얼마나 있는지 세고,
사람이 정답을 달아 **규칙이 어디까지 맞히는지** 재는 과정 전체다.

처음 하는 사람이 이 문서만 보고 끝까지 갈 수 있게 썼다. 클릭 단위로 적었다.
도구 자체의 설계나 휴리스틱이 궁금하면 [README.md](README.md)를 본다.

```
① 데이터 넣기  →  ② 분석 (터미널)  →  ③ 라벨링 (엑셀)  →  ④ 채점 (터미널)
   md/ 또는 data/    analyze.py        labels/라벨링.csv    label.py score
```

전체 소요: 숙소 5곳 기준 **수집 30분 + 라벨링 40분** 정도.

## 0. 준비 (한 번만)

| 필요한 것 | 확인 방법 |
|---|---|
| Python 3.10 이상 | 터미널에 `python --version` |
| 엑셀 또는 구글 시트 | CSV를 열 수 있으면 뭐든 |
| Chrome 또는 Edge | **직접 수집할 때만** 필요 (1-B) |

설치할 패키지는 **없다.** 세 스크립트 모두 파이썬 표준 라이브러리만 쓴다.

터미널을 열고 이 폴더로 이동해둔다. 앞으로 나오는 명령은 전부 여기서 친다.

```bash
cd labeling
```

> **Windows에서 한글이 `???`로 깨지면** 터미널에 `chcp 65001` 을 한 번 치고 다시 실행한다.

## 시작하기 전 — 내 경우는 어느 쪽인가

데이터가 들어오는 길이 **두 가지**다. 자기 경우만 보면 된다.

| 어떤 파일을 갖고 있나 | 어디에 넣나 | 읽을 곳 |
|---|---|---|
| **팀원에게 받은 `.md`** (`윤상_리조트_5성급_체인호텔.md` 같은 것) | **`md/` 폴더** | **아래 [1-A]** |
| 내가 브라우저로 직접 수집 | `data/` 폴더 | 아래 [1-B] |

둘을 **섞어도 된다.** `md2json.py`가 md를 `data/`에 json으로 풀어놓고,
`analyze.py`는 `data/`에 있는 걸 전부 읽어 같은 숙소끼리 합친다.

```
labeling/
├── md/       ← 팀원에게 받은 .md 를 여기에 넣는다   (직접 만들어야 함)
├── data/     ← 변환 결과 + 직접 수집한 .json      (자동 생성)
├── out/      ← 분석 결과                        (자동 생성)
└── labels/   ← 라벨링 CSV                       (자동 생성)
```

## 1-A. 팀원에게 받은 md 파일로 시작하기

### 1-A-1. `md` 폴더를 만들고 파일을 넣는다

`labeling/` 안에 **`md`** 라는 폴더를 만든다.
받은 `.md` 파일을 **이름 그대로** 거기에 넣는다. 여러 명 것을 한꺼번에 넣어도 된다.

```
labeling/md/
├── 윤상_리조트_5성급_체인호텔.md
├── 윤서_특가비환불_장기체류.md
├── 소윤_게스트하우스_모텔_저가숙소.md
└── 아고다_소윤_저가호텔.md
```

> 폴더 만들기가 귀찮으면 `python md2json.py` 를 한 번 그냥 실행해도 된다.
> `md` 폴더가 없으면 만들어주고 안내가 뜬다.

### 1-A-2. 변환한다

```bash
python md2json.py
```

```
  ✅ 윤상_리조트_5성급_체인호텔.md → 숙소 19곳 · 리뷰 224건 · 약관 38건
  ✅ 윤서_특가비환불_장기체류.md → 숙소 19곳 · 리뷰 227건 · 약관 32건
     ↳ 약관 4건은 붙일 숙소가 없어 제외 (리뷰 파트에 그 숙소가 없음)
  ...
📦 data 에 저장 — 숙소 67곳 · 리뷰 718건 · 약관 119건
   → 다음: python analyze.py
```

**이제 [2. 분석]으로 간다.** 1-B는 건너뛴다.

### md 파일이 갖춰야 할 형식

담당자마다 조금씩 달라도 받는다. 아래 둘 다 된다.

```markdown
## 리뷰 파트                     ## [리뷰 파트]
                                (대괄호가 있어도 됨)
[1] 숙소: 더 캡슐 명동(캡슐호텔)
리뷰: "[가격에 맞았습니다.] 3박 동안 머물렀습니다..."

## 약관 파트
[1] 체크인: 2026-10-15 / 숙소: 더 캡슐 명동 Basic Shared Dormitory
카드 요약: "예약 무료 취소 가능 - 2026년 10월 6일 전 예약 취소 시"
전문(자세히 보기): "유연한 예약! ..."        ← '원문:' 이라고 써도 됨
```

| 자주 나는 문제 | 원인과 해결 |
|---|---|
| `리뷰를 못 찾았습니다` 경고 | `## 리뷰 파트` 제목이 없거나, `리뷰: "..."` 의 **큰따옴표가 빠졌다** |
| 리뷰 건수가 실제보다 적다 | 리뷰 본문 안의 큰따옴표가 문장을 일찍 끊었다. 본문 안에서는 `'` 를 쓴다 |
| `약관 N건은 붙일 숙소가 없어 제외` | 약관 파트에만 있고 **리뷰 파트에는 없는 숙소**다. 문제가 아니며, 리뷰가 없으면 분석 대상도 아니다 |

> ### md로 들어오면 못 하는 것
> md에는 **작성일·평점·숙소 공식 표기**가 없다.
> 그래서 `최근 리뷰 가중`과 `"무료 주차라고 써놓고 유료였다"` 식의 **표기 충돌 탐지**는
> md 입력에서 동작하지 않는다. 비용 언급을 세고 라벨링하는 데는 지장이 없다.

## 1-B. 직접 수집해서 시작하기 — 브라우저로 리뷰 긁어오기

> **1-A로 시작했으면 이 절은 통째로 건너뛰고 [2. 분석]으로 간다.**
> 브라우저는 **Chrome 또는 Edge**여야 한다. Firefox·Safari는 저장 폴더 지정이 안 된다.

### 1-1. 숙소 페이지를 연다

아고다에서 숙소 하나를 골라 **상세 페이지**를 연다.
검색 결과 목록이 아니라, 객실과 후기가 다 보이는 그 페이지다.

### 1-2. 후기 영역까지 스크롤한다

마우스 휠로 **후기 섹션이 화면에 보일 때까지** 내린다.

> 왜 필요한가: 리뷰는 화면에 나타날 때 불러오는(lazy load) 방식이라,
> 한 번도 화면에 안 나온 섹션은 브라우저 안에 아예 존재하지 않는다. 스크롤을 건너뛰면 0건이 나온다.

### 1-3. 리뷰 언어를 한국어로 맞춘다

후기 영역 위쪽의 **"작성 언어"** 를 **한국어**로 바꾼다.

> 왜 필요한가: 분석기 키워드가 전부 한국어다(`주차비`, `보증금`, `조식`…).
> 일본어·영어 리뷰는 수집돼도 판정에서 전부 버려진다.

### 1-4. 개발자 도구를 연다

키보드 **`F12`** → 위쪽 탭에서 **`Console`** 을 클릭한다.

> `>` 기호가 있는 입력줄이 보이면 준비된 것이다.
> 처음 열면 "여기에 코드를 붙여넣지 마세요" 경고가 뜰 수 있는데,
> 시키는 대로 `allow pasting` 을 입력하면 풀린다.

### 1-5. 수집기를 붙여넣는다

에디터에서 **`collect-reviews.js` 파일 전체를 복사**(Ctrl+A → Ctrl+C)해서
콘솔에 붙여넣고 **Enter**.

성공하면 이렇게 뜬다:

```
✅ collect-reviews 준비됨 [버전 ...]
```

### 1-6. 저장 폴더를 지정한다 (한 번만)

콘솔에 그대로 친다:

```js
await pickSaveFolder()
```

폴더 선택 창이 뜨면 **`labeling/data`** 폴더를 고른다.
(폴더가 없으면 그 창에서 새로 만든다.)

> 이걸 해두면 이후 수집 결과가 자동으로 그 폴더에 저장된다.
> 건너뛰면 클립보드로만 복사돼서 직접 파일로 붙여넣어야 한다.

### 1-7. 수집한다

```js
await collectReviews({ maxPages: 40 })
```

`maxPages: 40`이면 약 200건이다. 진행 상황이 콘솔에 찍히고, 끝나면 종료 사유가 나온다.

| 끝났을 때 메시지 | 뜻 |
|---|---|
| `마지막 페이지` | 리뷰를 다 모았다 — 정상 |
| `maxPages 도달` | 40페이지까지만 모았다 — 더 필요하면 숫자를 올린다 |
| `내용이 안 바뀜` | 페이지 넘김이 막혔다 → 아래 "막힐 때" 참고 |

### 1-8. 다음 숙소로 넘어간다

**숙소 5~10곳**을 같은 방법으로 반복한다. 페이지를 옮기면 1-2부터 다시 하면 된다.

> **어떤 숙소를 고를까:** 리조트·5성급은 비용 언급이 <b>0.9%</b>, 호스텔·게스트하우스는 <b>14.6%</b>다.
> 같은 노력으로 사례를 훨씬 많이 얻으려면 **저가 숙소**를 고르고,
> 가능하면 리뷰를 **평점 낮은 순**으로 정렬해서 모은다.

### 막힐 때

| 상황 | 해결 |
|---|---|
| 페이지 넘김이 자꾸 멈춘다 | `watchReviews()` 를 친 뒤 **직접 1, 2, 3… 페이지를 클릭**하고, 다 되면 `await saveWatched()` |
| 리뷰가 아니라 객실 목록을 긁어온다 | `inspect.js`를 이어서 붙여넣고 **[탐색] 탭**에서 올바른 목록을 직접 클릭 |
| 후기 모달을 이미 열어놨다 | `await collectReviews({ skipModal: true })` |
| 그래도 안 되면 | Elements 탭에서 리뷰 목록을 클릭한 뒤 `await collectReviews({ container: $0 })` |

### 확인

`data/` 폴더에 `.json` 파일이 숙소 수만큼 생겼으면 성공이다.

## 2. 분석 — 규칙으로 1차 판정

터미널에서:

```bash
python analyze.py
```

이렇게 나오면 성공이다:

```
📂 5개 숙소 파일 로드
✅ 저장: out/집계.md
✅ 저장: out/리포트.html
✅ 저장: out/후보.jsonl  (48건, 라벨링용)
```

### 뭐가 만들어졌나

| 파일 | 언제 보나 |
|---|---|
| **`out/리포트.html`** | **가장 먼저 열어볼 것.** 브라우저로 열면 판정 근거가 문장에 색칠돼 있다 |
| `out/집계.md` | 숫자 요약 |
| `out/애매한-문장.md` | 규칙이 못 가른 문장 — 회의용 |
| `out/후보.jsonl` | 다음 단계(라벨링)의 입력 |

**`out/리포트.html`을 더블클릭해서 한 번 훑어보자.** 규칙이 어떤 근거로 판정했는지가 보인다.

```
위치도 좋고 깨끗했어요. [주차]는 [무료]라서 편했습니다.
                        ↑키워드  ↑부정단서(회색)

다 좋았는데 [주차비]를 현장에서 [따로] [받더라]고요.
             ↑키워드            ↑비용단서(초록)
```

### 자주 나는 오류

| 메시지 | 원인과 해결 |
|---|---|
| `data 에 읽을 수 있는 .json 이 없습니다` | 수집 파일이 다른 폴더에 있다. 스크립트가 어디 있는지 알려주니 그대로 옮긴다 |
| `📁 데이터 폴더를 만들었습니다` | 아직 수집 전이다. 1단계부터 한다 |
| 한글이 `???` 로 깨짐 | `chcp 65001` 후 재실행 |

## 3. 라벨링 — 사람이 정답 달기

규칙은 키워드와 주변 단서만 본다. **문장의 뜻을 못 본다.** 사람이 정답을 달아야
규칙이 어디서 틀리는지 잴 수 있고, 그 숫자가 곧 "모델이 필요한 이유"가 된다.

### 3-1. 라벨링 파일 만들기

```bash
python label.py init
```

```
✅ labels/라벨링.csv
   전체 48건 · 이미 채운 라벨 0건 유지 · 새 후보 48건
```

> ### ⚠ 왜 `후보.jsonl`에 직접 안 쓰는가
> `analyze.py`는 실행할 때마다 `out/` 폴더를 **통째로 다시 쓴다.**
> `후보.jsonl` 안에서 라벨을 채우면 다음 분석 때 **전부 날아간다.**
> `labels/` 폴더는 `analyze.py`가 건드리지 않으므로 안전하다.

### 3-2. 엑셀로 열어서 `gold` 칸을 채운다

`labels/라벨링.csv`를 엑셀이나 구글 시트로 연다.
**`gold` 칸(B열)만 채우면 된다.** 나머지는 참고용이다.

| 넣는 값 | 뜻 |
|---|---|
| **`1`** | 실제로 **돈을 더 냈다 / 내야 한다**는 얘기다 |
| **`0`** | 아니다 — 무료였거나, 비용 얘기가 아니거나, 오히려 칭찬이다 |
| **`?`** | 사람이 봐도 모르겠다 (보류) |

아직 안 채운 줄이 **맨 위로** 정렬돼 있으니 위에서부터 내려가면 된다.

### 3-3. 판단 기준

**`1`을 주는 경우** — 문장 안에서 돈이 실제로 오갔거나, 오갈 것이 확정된 경우

> "주차장이라고 되어있어서 당연히 무료인줄 알았는데 나중에 보니 **유료주차**라네요" → `1`
> "세탁기를 사용하려면 **추가로 30바트를 지불**해야 하며" → `1`
> "**조식 포함으로 예약했는데** 마지막 날 **추가 요금을 받고**" → `1`
> "체크인할 때 **100엔을 결제해야** 하는데" → `1`

**`0`을 주는 경우**

> "지하주차장도 **무료**이니 참고요~" → `0` (오히려 무료였다)
> "**인원 추가 요금이 있다는 안내가 명확해서 좋았어요**" → `0` (칭찬이다. 규칙은 이걸 `1`로 착각한다)
> "**청구**역에서 도보 1분" → `0` (지하철역 이름이다. 비용과 무관)
> "조식이 맛있었어요" → `0`

**`?`를 주는 경우**

> "청소비가 좀 비싼 편이지만" → 본인이 낸 건지 일반론인지 문장만으로는 모른다

### 3-4. 세 가지 요령

1. **문장만 보고 판단한다.** 리뷰 전체 맥락을 상상해서 채우면 사람마다 답이 달라진다.
2. **`rule_verdict` 칸을 먼저 보지 않는다.** 규칙 판정을 보고 나면 거기 끌려간다.
   D열(`fee_type`)과 F열(`sentence`)만 보고 정하는 게 좋다.
3. **애매하면 `?`.** 억지로 0이나 1을 넣는 것보다 보류가 낫다. `?`는 채점에서 제외된다.

### 3-5. 저장

**CSV 형식 그대로** 저장한다. 엑셀이 "형식을 유지하시겠습니까?" 물으면 **예**.
`.xlsx`로 저장하면 다음 단계에서 못 읽는다.

## 4. 채점 — 규칙이 어디까지 맞혔나

```bash
python label.py score
```

```
=== 규칙 베이스라인 성적표 ===

[ambiguous 를 '아님'으로 처리 (엄격)]
  Precision 0.812  Recall 0.591  F1 0.684
  TP 13  FP 3  FN 9  TN 23

[규칙 판정별 실제 정답 비율]
  mention      16건 중 실제 비용 언급   13건 (81.3%)
  ambiguous    12건 중 실제 비용 언급    7건 (58.3%)
  negated      20건 중 실제 비용 언급    2건 (10.0%)

→ 모델이 회복해야 할 구간: ambiguous 12건 중 7건이 실제 비용 언급.
```

*(숫자는 예시다. 실제 값은 데이터에 따라 다르다.)*

### 이 표를 읽는 법

| 줄 | 뜻 |
|---|---|
| `Precision` | 규칙이 "비용이다"라고 한 것 중 **진짜 비율**. 낮으면 오탐이 많다 |
| `Recall` | 진짜 비용 언급 중 규칙이 **잡아낸 비율**. 낮으면 놓치는 게 많다 |
| `mention 중 실제` | 규칙의 자신 있는 판정이 얼마나 믿을 만한지 |
| **`ambiguous 중 실제`** | **가장 중요한 숫자.** 규칙이 포기한 것 중 실제 정답이 몇 개인지 = 모델이 벌어올 수 있는 양 |

**두 가지 기준으로 같이 보여주는 이유:** `ambiguous`를 실패로 칠지 성공으로 칠지에 따라
점수가 크게 달라진다. 한쪽만 보고하면 유리하게 고른 것처럼 보이니 둘 다 적는다.

결과는 `labels/채점.md`에도 저장된다. **문장이 안 들어가므로 이 파일은 커밋해도 된다.**

## 5. 리뷰를 더 모았을 때

python analyze.py      # 새 데이터까지 다시 분석

✅ labels/라벨링.csv
   전체 92건 · 이미 채운 라벨 48건 유지 · 새 후보 44건

새로 추가된 44건이 파일 맨 위로 올라온다. 거기서부터 이어서 채우면 된다.

> 문장이 같으면 같은 `cand_id`가 나오도록 만들어서 병합된다.
> **`cand_id` 칸은 절대 수정하지 말 것** — 고치면 매칭이 깨져 라벨이 유실된다.

## 커밋해도 되는 것 / 안 되는 것

| 경로 | 커밋 | 이유 |
|---|---|---|
| `collect-reviews.js` · `analyze.py` · `label.py` | ✅ | 코드 |
| `labels/채점.md` | ✅ | 숫자만 있고 리뷰 문장이 없다 |
| `실측-로그.md` | ✅ | 집계 결과 |
| `md/` | ❌ | 팀원에게 받은 **리뷰 원문** |
| `data/` | ❌ | 변환·수집 결과. 리뷰 원문이 들어 있다 |
| `out/` | ❌ | 리포트에 리뷰 원문이 들어간다 |
| `labels/라벨링.csv` | ❌ | `sentence` 칸에 리뷰 원문이 들어간다 |

`.gitignore`에 이미 걸려 있어서 실수로 올라가지 않는다.
팀원과 라벨을 공유해야 하면 구글 드라이브 같은 별도 경로를 쓴다.
