# ClearBooking : 호텔 실결제액·취소 위약금

아고다(agoda.com) 숙소 예약 페이지에서 세금·수수료 포함 실제 결제 총액, 취소 시
예상 손실액, 더 나은 요금제 옵션, 리뷰 속 숨은 비용을 한 장의 브리핑 카드로
자동으로 보여주는 Chrome Extension. **크롬 웹스토어에 제출된 실제 코드** — 이
폴더가 source of truth다.

Agoda와 제휴·승인·후원 관계가 없는 비공식 확장 프로그램이다.

## 실행 방법

1. `chrome://extensions` 접속 → 개발자 모드 On
2. "압축해제된 확장 프로그램을 로드합니다" → 이 폴더(`extension/`) 선택
3. 아고다(agoda.com) 숙소 상세 페이지 방문 — 버튼 없이 자동으로 브리핑 카드가 뜬다
   (페이지 진입 후 약 1~2초 뒤)
4. 검색결과 목록 페이지에서는 각 숙소 카드에 안전도 배지가 붙는다

## 주요 기능

- **실제 결제 총액**: 표시 가격과 세금·수수료 포함 총액을 비교해 실제 결제금액을
  보여준다.
- **취소 리스크**: 취소정책 원문을 분석해 위약금이 시작되는 시점과 취소 시 예상
  손실액(타임라인)을 계산한다.
- **더 나은 옵션 비교**: 현재 선택한 요금제와 무료취소 등 다른 옵션의 가격 차이와
  조건을 함께 비교한다.
- **리뷰 속 추가비용 탐지**: 공개 리뷰를 분석해 도시세·숙박세, 보증금, 조식,
  시설이용료 등 현장에서 추가로 발생할 수 있는 비용 언급을 찾아 표시한다.

## 아키텍처

```
content.js       페이지 변화 감지(MutationObserver, SPA 라우팅) → 언제 다시
                 스캔할지 판단하는 오케스트레이션 레이어. 자체 로직은 없음.
  ↓
pricing.js       요금제 블록 탐색 + 실제 총액 계산
cancellation.js  취소정책 원문 탐색 + 분류(무료취소/단계별 위약금/환불불가 등)
pageClaims.js    페이지에 이미 명시된 비용 문구 추출 (리뷰 신호와 중복 제거용)
reviews.js       리뷰 텍스트에서 규칙 기반 비용 신호 1차 추출
reviewtab.js     리뷰 API 호출·페이지네이션 (review-engine/*.ts에서 수동 빌드)
badges.js        검색결과 목록 페이지의 숙소별 안전도 배지
  ↓
briefing.js      위 모듈 결과를 모아 브리핑 카드 렌더링 + 리뷰 분류 서버(Cloud
                 Run) 호출 + 전체 오케스트레이션 진입점(runBriefing)
```

`content.js`가 스캔 시점을 결정하고 `briefing.js`가 실제 판단·렌더링을 담당한다.
나머지 모듈은 각자의 영역(가격/취소조건/리뷰/배지)만 읽고 판단하는 순수 함수에
가깝다.

## 사이트 어댑터 (다른 OTA 붙이기)

사이트마다 달라지는 부분(요금 행 선택자, 숙소 ID, 리뷰 수집 방법 등)은 `sites.js`의
레지스트리에 **어댑터 객체 하나를 등록**하는 방식으로 분리했다. 공용 코드(pricing /
cancellation / badges / content / briefing의 렌더링)는 사이트를 직접 알지 못하고
`window.__ccSites`에서 현재 사이트의 어댑터를 조회한다.

- **계약(필수/선택 항목, Review 형태)은 [`sites.js`](sites.js) 상단 주석이 정본이다.**
  필수는 `id · displayName · matches · isListingPage · hotelId` 다섯 개뿐이다.
- 아고다 어댑터는 `briefing.js` 맨 끝에 등록돼 있다. 아고다 로직은 옮기지 않고 기존 함수를
  그대로 노출만 했다(게시본 v1.0.0과 동작을 같게 유지하려는 의도).
- 새 OTA는 **새 파일**(`sites/<id>.js` 등)에 어댑터를 만들고, `manifest.json`의
  `content_scripts.js`에 추가한다(`sites.js`보다 뒤, **`content.js`보다 앞** — 첫 스캔 전에
  등록이 끝나 있어야 한다).
  공용 파일 수정이 필요해지면 그건 어댑터 계약이 부족하다는 신호이니 먼저 논의한다.
- 사이트 특성에 따라 쓰는 **선택 훅**: `hints.rateRowVisibleOnly`(숨은 행 제외),
  `price.finalPrice(scope)`(라벨 없이 "세금 포함"만 붙는 가격 읽기),
  `cancellation.{revealTrigger, modal, modalText, parse}`(정책 원문이 모달 안에만 있거나 문구가 달라
  직접 해석해야 하는 사이트), `stayDates(doc)`(URL 등 화면 텍스트보다 정확한 날짜 출처).
  위약금이 퍼센트가 아니라 절대 금액(`lossSteps[].amount`)으로 적히는 사이트도 지원한다.
  모두 생략하면 아고다와 같은 공용 경로를 탄다. 어댑터 파일은 `sites/` 폴더에 둔다
  (**스토어 zip을 만들 때 이 폴더도 포함해야 한다**).
- 리뷰 수집이 준비되지 않은 사이트는 `reviews`를 생략하거나 `source: "none"`으로 둔다.
  가격·취소 브리핑은 동작하고, 리뷰 자리에는 "아직 지원하지 않아요" 안내만 나온다.
- 등록 실패(필수 항목 누락, id 중복)는 예외 대신 콘솔의 `[cc] 어댑터 등록 실패 …`로 남는다.
- 호스트 권한: 새 사이트의 도메인은 `manifest.json`의 `host_permissions`와
  `content_scripts.matches`에 추가해야 하고, 스토어 개인정보 탭·설명·비공식 고지도 함께 고친다.

## 데이터 흐름 (개인정보 관련)

- 가격·취소조건 계산은 브라우저 안에서만 이뤄진다 — 외부로 전송되지 않는다.
- 리뷰 텍스트만 숨은 비용 분류를 위해 자사 분류 서버(Google Cloud Run)로 전송되고,
  분류 결과만 돌려받는다. 서버는 전송된 텍스트를 저장하지 않는다.
- 자세한 내용은 [개인정보처리방침](https://dldmsals.github.io/ClearBooking/privacy.html)과
  [`docs/chrome-store-privacy-tab.md`](../../docs/chrome-store-privacy-tab.md) 참고.

## 알려진 한계

1. **DOM 기반 리뷰 자동수집 폴백은 비활성화 상태** — 리뷰 API가 실패하면(아고다
   쪽 문제 등) 자동으로 페이지를 긁어오는 대신 "확인 필요" 안내만 뜬다. 예전에
   이 폴백의 자동클릭 로직이 페이지 다른 UI(날짜/인원선택 팝업)를 잘못 건드리는
   사고가 있었고, 근본 원인은 별도로 고쳤지만(아래 참고) 자동클릭 경로 자체는
   안전을 위해 계속 꺼둔 상태다. 자동클릭 없는 폴백 재설계는 다음 라운드 작업.
2. **한국어 화면 기준** — 브라우저/계정 언어가 한국어가 아니면 텍스트 매칭 정확도가
   떨어질 수 있다.
3. **그림자 DOM/iframe 내부 요소는 탐지 대상 밖** — `document.querySelectorAll` 기반
   스캔이라, 관련 UI가 iframe 안에 있으면 보지 못한다.

## 실측으로 확인된 버그와 수정 (2026-09-17)

캘린더/인원선택 창이 저절로 계속 넘어가는 사고가 있었다. 처음엔 리뷰탭 자동클릭
페이지네이션을 의심해 그쪽을 여러 차례 고쳤지만(`reviewtab.js`의 검색 범위 제한,
`briefing.js`의 취소정책 자동펼치기 스코프 제한 등 — 전부 그 자체로는 정당한
방어 로직이라 유지) 재현 로그에 해당 코드가 전혀 안 찍혀서 원인이 아닌 것으로
판명됐다.

진짜 원인은 `content.js`의 "모달이 뜨면 디바운스 없이 즉시 재스캔" 규칙이었다 —
`role="dialog"`/`aria-modal="true"`만 보고 판단해서, 아고다의 날짜/인원선택
팝업도 똑같이 걸려 그 순간 무거운 동기 스캔이 메인스레드를 점유했고, 그게 아고다
자체 팝업의 초기화 타이밍과 충돌해 팝업이 스스로 상태를 두 번 진행시켰다(우리가
클릭한 게 아니라 우리 스캔이 타이밍을 방해한 것 — DOM breakpoint로 재현 순간의
호출스택을 직접 확인해 확정). 검색바(`#SearchBoxContainer`) 영역의 DOM 변화는
감지 대상에서 제외해 해결했다.

## 폴더 구조

```
extension/
├── manifest.json
├── sites.js          # 사이트 어댑터 레지스트리 + 계약 (가장 먼저 로드)
├── sites/
│   ├── tripcom.js    # Trip.com 어댑터 (가격·취소·리뷰·모델 — 서버 CORS 가 *.trip.com 을 허용하도록 수정됨)
│   └── bookingcom.js # 부킹닷컴 어댑터 (가격·취소·체크인/체크아웃·리뷰 — 리뷰 GraphQL 요청
│                      # 구조(query 문서 포함) 전부 실측 완료)
├── content.js       # 오케스트레이션 (스캔 시점 판단)
├── pricing.js
├── cancellation.js
├── pageClaims.js
├── reviews.js
├── reviewtab.js      # review-engine/*.ts에서 수동 빌드 — 소스 고치면 여기도 반영할 것
├── badges.js
├── briefing.js       # 메인 오케스트레이션 + 카드 렌더링 + 아고다 어댑터 등록
├── paymentCurrency.js  # 결제 페이지 전용, 완전히 독립된 스크립트 — 위 브리핑 카드와
│                       # 무관. 화면 KRW와 실제 결제 통화가 다르면 읽기 전용 안내만 띄운다
├── icon16.png / icon48.png / icon128.png
└── promo-440x280.png
```
