# LLM 비교 실험 — 자체 분류 모델 vs OpenRouter LLM

2026-09-23 · 목적: 리뷰 추가비용 판정에 **학습 모델을 쓰는 것이 타당한가**를 정확도·지연·비용·일관성으로 확인

## 조건

| 항목 | 값 |
|---|---|
| 평가셋 | 사람 라벨 282건 (`label_source ∈ {human, human(cost_info=N)}`, ko 150 · en 132). `?` 라벨은 원래 채점에서 제외돼 있음 |
| **공정 비교 구간** | 그중 **val+test 71건** — 우리 모델이 학습에 본 적 없는 행. LLM 은 아무것도 학습 안 했으므로 여기서만 나란히 비교 |
| 프롬프트 | `labeling/라벨링-가이드.md` §3-3 판단 기준을 그대로 (예시 8개 포함). 출력 0/1 강제 |
| LLM | OpenRouter 경유 `openai/gpt-4o-mini`, `anthropic/claude-haiku-4.5` · temperature 0 · reasoning low |
| 우리 모델 | Cloud Run · 4GiB · 최소 인스턴스 0. 개선 전 = 리비전 00006 (ko `klue/roberta-base`, 2 vCPU). 개선 후 = 리비전 00013 (ko `klue/roberta-small` 재학습, 4 vCPU, 09-23 라이브). en 은 둘 다 `distilbert-base-uncased` |
| 측정 위치 | 사용자 맥(서울)에서 실제 HTTP 왕복 — 익스텐션이 겪는 조건 |
| 지연 단위 | **페이지 1회 = 후보 문장 40개** (ko 3페이지 + en 2페이지) × 3회, 순차, 웜업 후. LLM 은 40문장을 한 호출에 배치 |
| 비용 | OpenRouter 응답 `usage` × 실제 단가. 우리 서버는 Cloud Run 표준가로 환산 |
| 일관성 | 같은 100문장을 3회 → 3회 모두 같은 답인 비율 |

## 정확도 (Macro F1 · MCC)

| | **우리 모델** | gpt-4o-mini | claude-haiku-4.5 |
|---|---|---|---|
| **val+test 71건 (공정)** | **0.756** · +0.51 | 0.687 · +0.47 | **0.761** · +0.52 |
| 한국어 36 | 0.776 · +0.57 | 0.688 · +0.52 | **0.819** · +0.69 |
| 영어 35 | **0.735** · +0.49 | 0.685 · +0.43 | 0.694 · +0.43 |
| 전체 282 (우리 모델은 train 포함 → 참고만) | 0.871 · +0.74 | 0.690 · +0.45 | 0.721 · +0.44 |
| 규칙이 `negated` 로 놓친 실제 비용 19건 — 재현율 | **0.79** | 0.47 | 0.68 |
| 오류 유형 (val+test) FP / FN | 8 / 7 | **2 / 20** | 7 / 8 |

- 우리 모델 ≈ Haiku. n=71 이라 ±0.1 은 잡음 — "비긴다"가 정직한 표현
- gpt-4o-mini 는 **FN 20건**: 비용이 있는데 없다고 함. 중간발표 피드백("미탐이 더 나쁘다")과 반대 방향으로 틀림
- 규칙이 놓친 19건에서 격차가 가장 큼 — 학습 데이터의 "negated 인데 실제 비용" 42건이 만든 차이. 학습 모델의 존재 이유가 여기 있음

## 지연 · 비용 · 일관성 (페이지 40문장)

| | 우리 모델 (개선 전) | **우리 모델 (개선 후, 라이브)** | gpt-4o-mini | claude-haiku-4.5 |
|---|---|---|---|---|
| 지연 p50 / p95 / max | 8.6s / 14.1s / 16.1s | **1.2s / 1.5s / 1.6s** | 2.1s / 4.6s / 5.0s | 1.8s / 3.3s / 3.4s |
| 페이지당 비용 | $0 (무료 한도 내) · 초과 시 $0.0003 | **$0** (무료 한도 내) · 초과 시 $0.0003 | $0.0003 | $0.003 |
| 3회 일관성 | 100% (결정적) | 100% (결정적) | 98% | 100% |
| 배치 응답 파싱 성공 | 100% | 100% | 98% | 100% |
| 데이터 반출 | 서울 리전 · 미저장 · 국외이전 고지 불필요 | 동일 | 미국 제3자 | 미국 제3자 |
| 온디바이스 전환 | 가능 (ONNX/WASM) | 가능 | 불가 | 불가 |

**개선 전 → 후에 바꾼 것**

| 단계 | 바꾼 것 | p50 | p95 | 출력 |
|---|---|---|---|---|
| 시작 (리비전 00006) | 배치 32 · 정렬 없음 · 2 vCPU | 8.0s | 14.0s | 기준 |
| ① serve.py | 문장 길이순 정렬 + 8개 배치 | 3.8s | 5.2s | 동일 |
| ② Cloud Run | 4 vCPU (같은 이미지) → 리비전 00009 | 2.0–3.5s | 2.6–4.5s | 동일 |
| ③ 한국어 모델 | `klue/roberta-base` → `roberta-small` 재학습 (같은 레시피) → 리비전 00013 | **1.2s** | **1.5s** | 정확도 동일 (아래) |

- 원인: 네트워크는 0.1s. 서버 계산 10.3s 의 대부분이 패딩 — 문장 토큰 길이 중앙값 31·최대 165 인데 `padding=True` 가 배치 32개를 최장 문장에 맞춰 늘림. 1문장 0.13s ↔ 40문장 10.3s 로 비선형이었음
- ② 의 수치가 흔들리는 건 리비전마다 배정되는 물리 CPU 가 달라서 (같은 이미지·같은 torch 2.14). Cloud Run 이 CPU 세대를 보장하지 않으므로 통제 불가
- ② 는 vCPU-초 과금이라 요청당 비용 동일, 메모리 GiB-초는 절반. 최소 인스턴스 0 이라 유휴 비용 없음
- **INT8 양자화·ONNX 는 보류**: 로컬 실측에서 판정이 바뀜 (ko 2/150 · en 4/132, val+test Macro F1 −0.03). 공짜가 아니라 우선순위 뒤로
- ③ small 은 base 와 test 145건 Macro F1 동일(0.860), 사람 라벨 36건에서 틀린 개수 동일(7개, base 는 미탐 5 · small 은 미탐 3). 6층이라 계산 절반. 상세는 `model-server/METRICS-ko-roberta-small.md`
- 같이 반영: PR #11 Booking.com 지원에 맞춰 서버 CORS 허용 목록에 `booking.com` 추가

## 결론

```
정확도     비김 — Haiku 수준, 싼 LLM 보다 위, 미탐이 적음
비용       우리 우위 — Haiku 의 1/10, 4o-mini 와 동급이면서 한도 내 $0
프라이버시  우리 우위 — 국외이전 고지 불필요, 온디바이스 경로 있음
지연       비김 — 개선 전 4배 느렸으나 개선 후 1.2s 로 Haiku(1.8s)보다 빠름
수정 용이   LLM 우위 — 프롬프트 한 줄 vs 재학습
```

> 정확도는 Haiku급, 비용은 1/10, 데이터는 서울 밖으로 안 나간다. 지연은 4배 느렸던 것을 패딩 제거·4 vCPU·small 재학습으로 Haiku 보다 빠르게 만들었다.

## 재현

```
scratchpad/llm-bench/bench.py  (하네스) · eval_human.jsonl (평가셋) · latency_pages.json (페이지) · results/
python bench.py accuracy --models openai/gpt-4o-mini,anthropic/claude-haiku-4.5
python bench.py latency  --repeats 3 · python bench.py consistency --repeats 3
python measure_tag.py    (우리 서버 개선 전/후, 트래픽 0% 태그 리비전 대상)
```
키는 `~/.config/clearclause/openrouter.env` (레포 밖). 하네스·평가셋은 리뷰 원문을 포함하므로 레포에 커밋하지 않음.
