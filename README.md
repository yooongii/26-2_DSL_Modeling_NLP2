## Project Overview

숙박 예약 직전, 소비자가 판단에 필요한 정보 — **실제 결제 총액 / 취소 시 손실 / 숨은 추가비용** — 은 한 화면에 모여 있지 않습니다. 취소 조건은 팝업을 열어야 보이고, 추가비용은 설명란이 아니라 리뷰 곳곳에 흩어져 있으며, 목록에 보이는 가격과 실제 결제 총액도 다른 경우가 있습니다.

처음에는 숙박 예약 페이지의 **다크패턴(거짓 긴급성, 사전선택 등 위법 UI)** 을 탐지하는 것이 목표였습니다. 그러나 실제 Agoda·Booking.com·Trip.com 화면을 분석한 결과, 명확한 위법 다크패턴은 예상보다 드물었고, 대신 **예약 판단에 필요한 정보가 여러 위치에 흩어져 있어 사용자가 직접 찾아 계산해야 하는 문제**가 훨씬 반복적으로 나타났습니다. 그래서 다크패턴 탐지에서 **예약 판단 지원**으로 방향을 전환했습니다.

**ClearBooking**은 현재 보고 있는 숙박 옵션의 가격·취소조건·추가비용을 분석해, 예약 직전 필요한 판단을 브리핑 카드 한 장으로 제공하는 Chrome Extension입니다.

> **중간발표(2026.09 초)**: Agoda 단일 사이트, 한국어 리뷰만 지원하는 로컬 데모
> **최종(2026.10)**: Agoda·Trip.com·Booking.com 3사 지원, 한국어·영어 리뷰 동시 분석, Chrome 웹스토어 정식 배포(v1.1.0)

## Pipeline

```
         아고다 · 트립닷컴 · 부킹닷컴
                    │
            사이트 어댑터 (sites.js)
                    │
   3사 공통 인터페이스로 가격·취소조건·리뷰 읽기
                    │
   ┌────────────────┼────────────────┐
   │                │                │
Price Truth      Terms IE         Review IE
세금·수수료·     규칙 기반 파서    KLUE-RoBERTa(ko)
추가인원 요금     취소 조건 →      DistilBERT(en)
반영 → 실제 총액  D-day 구간별 %    리뷰 → 비용 신호 0/1
   │                │                │
   │                │         Cloud Run 분류 서버
   │                │         (문장만 전송, 응답 후 즉시 폐기)
   └────────────────┴────────────────┘
                    │
              브리핑 카드
  예약 금액 · 취소 리스크 타임라인 · 추가비용 가능성 ·
  더 나은 옵션 · 저장 옵션 · 무료취소 마감 캘린더 등록
```

리뷰 분류는 두 단계로 나뉩니다. **유형**(주차·조식·보증금 등)은 키워드 규칙 엔진이 정하고, **모델**은 그 문장이 "진짜 비용을 말하는지"만 이진으로 판단합니다. 중간발표 때 유형 10종을 모델이 직접 분류하도록 시도했으나 9종이 F1 0.000에 가까울 정도로 실패했고, 역할을 분리한 뒤에야 안정적인 성능이 나왔습니다.

## Data

최종 학습 데이터는 "리뷰 전문"이 아니라 "규칙 엔진이 추출한 비용 키워드 문장" 단위로 재수집·재라벨링했습니다.

| | 한국어 | 영어 |
|---|:---:|:---:|
| 문장 수 (train / val / test) | 982 (693 / 144 / 145) | 790 (555 / 118 / 117) |
| 키워드 포함 비율 | 100% | 88% |
| 양성률 | 67.6% | 64.6% |
| 사람 라벨 | 150건 (15%) | 132건 (17%) |
| LLM 라벨 | 832건 (85%) | 658건 (83%, 사람 검수 보정) |
| 분할 기준 | 숙소 단위 누수 검사 | 문장 중복 0건 |

라벨링 기준: `1` = 돈이 실제로 오갔거나 확정(예: "유료주차라네요") · `0` = 무료였거나 칭찬(예: "지하주차장도 무료") · `?` = 문장만으로 판단 불가 → 채점 제외

LLM이 애매해하는 문장 위주로 282건(한국어 150 + 영어 132)을 직접 라벨링해 LLM 라벨링을 보정하고, 평가 골드셋으로 활용했습니다.

## Model

| | 한국어 | 영어 |
|---|---|---|
| 베이스 모델 | `klue/roberta-small` | `distilbert-base-uncased` |
| 역할 | 후보 문장의 비용 신호 유무(이진) 판정 | 동일 |
| 서빙 | Google Cloud Run (서울), `lang` 파라미터로 두 모델 서빙 | |

**파이프라인**: 리뷰 → 언어 감지(문자 비율) → 규칙 분석기(비용 키워드 후보 문장 추출) → 언어별 모델 → 비용 확률 반환

**서버 지연 최적화** — 문장 40개 기준 응답시간(p50)을 8.6초 → 1.2초로 단축:
1. 길이순 정렬 후 배치 묶기 (패딩 낭비 제거, 결과 동일) → 3.8초
2. CPU 2 → 4 vCPU 증설 (요청당 비용 차이는 거의 없음)
3. 한국어 모델 12층(base) → 6층(small) 교체, 정확도 유지(F1 0.860) → 1.2초

### 최종 모델 성능 (베이스라인 대비)

| 구분 | 한국어 test 145 · Macro F1 / MCC | 한국어 사람라벨 36건 · F1 | 영어 test 117 · F1 | 영어 사람라벨 18건 · F1 |
|---|:---:|:---:|:---:|:---:|
| 전부 양성으로 예측 | 0.403 / 0.000 | — | — | — |
| 키워드 규칙만 | 0.643 / +0.317 | — | 0.609 | 0.533 |
| **최종 모델** | **0.860 / +0.726** | **0.750** | **0.911** | **0.870** |

### 자체 모델 vs LLM API

사람이 라벨링한 데이터 중 학습에 쓰지 않은 71건으로 비교 (프롬프트는 라벨링 가이드 그대로, temperature 0).

| | Macro F1 · MCC | 지연(p50, 40문장) | 페이지당 비용 | 데이터 반출 |
|---|:---:|:---:|:---:|:---:|
| **자체 모델** | 0.756 · +0.51 | **1.2s** | **$0** (한도 내) | 서울 리전 · 미저장 |
| gpt-4o-mini | 0.687 · +0.47 | 2.1s | $0.0003 | 미국 제3자 |
| claude-haiku-4.5 | 0.761 · +0.52 | 1.8s | $0.003 | 미국 제3자 |

사용자 1,000명(월 60만 페이지) 기준 월 비용: 자체 모델 **약 $100** vs Haiku **약 $1,900**. 정확도는 Haiku와 대등하면서 비용·속도·데이터 통제 측면에서 유리해 자체 모델을 최종 채택했습니다.

### 한계
- 검증은 아직 소수 숙소·표본 중심(예: 공개 리뷰 131건 사례). 다양한 숙소 유형 전반의 재현율은 추가 검증이 필요합니다.
- 사전에 없는 새로운 비용 표현은 규칙 엔진의 후보 문장 단계에서부터 제외되어 모델이 볼 기회가 없습니다.
- 가격 변동 추적(1~24시간 타임라인)은 미구현 — Agoda가 반복적인 가격 수집(크롤링)을 차단

## Usage

### 확장 프로그램 설치 (로컬 개발용)
```
1. chrome://extensions → 개발자 모드 켜기
2. "압축해제된 확장 프로그램을 로드합니다" → extension/ 폴더 선택
3. 아고다 · 트립닷컴 · 부킹닷컴 숙소 상세 페이지 방문 — 자동으로 브리핑 카드 표시
```
리뷰 탭의 모델 판정은 배포된 Cloud Run 서버를 사용합니다. 로컬에서 직접 띄우려면 `model-server/팀원-실행법.md` 참고.

### 분류 서버 로컬 실행
```bash
cd model-server
pip install -r requirements.txt
python serve.py --model klue/roberta-small --model-en distilbert-base-uncased
```
